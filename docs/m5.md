## Controls and compatibility

The default v2 preview builds a **traditional** venue. The available themes are:

| Theme       | Engineered run-offs                        | Surroundings and containment                           |
| ----------- | ------------------------------------------ | ------------------------------------------------------ |
| Club        | Mostly grass, selected gravel              | A small garage complex, modest stands and guardrails   |
| Traditional | Gravel, grass and selected tarmac          | Tyre barriers, garage blocks, marshal posts and stands |
| Modern      | Predominantly paved escapes, grass infield | Modular impact barriers and a larger facility complex  |
| Desert      | Engineered tarmac plus sand                | Concrete containment, pale sand and dry bushes         |

Kerbs have **forgiving 35 mm** and **raised 75 mm** profiles. Both use the existing
0.9 m broad shape, tapered entry/exit heights and red/white stripes measured in
world distance. Fine individual teeth are not collision geometry.

Disable **Pit lane & service access** for a simpler venue, or disable **Build
circuit facilities** to recover the original undressed v2 result. Legacy v1 and
the authored M3 proving circuit remain independent fixtures. The M4 layout seed,
length, rhythm and same-land route alternatives still control the racing road.

Scenery density and its own seed change vegetation without changing run-off,
pit geometry, barriers, solid buildings, road meshes or car settings. A scenery-only
preview reuses the cached construction result in a worker. Any venue input change
invalidates the old preview; overlay changes leave it valid. Loading preserves the
vehicle setup and disposes the previous view and colliders.

**Export recipe** includes the v2 layout recipe, a separate version 1 venue recipe,
accepted definition, report and geometry/scenery fingerprints. The JSON is
inspectable, downloadable and selectable for ordinary keyboard copying. Venue
settings have separate browser storage; existing car saves are not migrated.

Generated test starts include the grid, far sector, summit, tightest corner, pit
lane, an apex kerb and a suitable loose run-off where present. **R** resets to the
selected start. The map shows **PIT LANE · 50 KM/H** when driving in the branch;
this is guidance, not an automatic speed limiter. Corner speed guides likewise do
not restrict throttle or replace the player's judgement.

**Surface sound** is off initially. Enabling it starts local synthesized rolling,
kerb and loose-surface feedback from the contacting wheels. Pausing or hiding the
app silences it. Engine audio and a complete presentation/audio mix remain M8 work.

## Construction method

M5 is a separately versioned pass over an accepted M4 circuit. It preserves the
centreline, elevation, bank and racing widths. It does not select a substitute seed
or silently return an undressed venue if construction fails.

1. Sample actual signed curvature into meaningful corners. Place short outside
   setup/exit zones and inside apex zones, preserving gaps between kerbs. Suppress
   kerbs beside the pit merges. Placement follows geometry rather than striping
   the entire lap boundary.
2. Survey available lateral space against the closest road legs and the inner
   offset-curvature limit. Smooth conservative caps prevent opposite run-offs
   from meeting across a folded infield.
3. At each selected corner entry, trace three straight-ahead/understeer rays from
   the outside setup line. Project their points onto the road's local coordinates,
   retaining only trajectories that fit the available space. Widen the appropriate
   run-off around these paths, with longitudinal tapers and theme-specific material.
4. Fit an explicit pit branch beside the level grid. Its entry/exit join near the
   racing edge, ease to a separate 4.2 m touring / 5 m GP lane and leave room for
   the pit wall. Build a paved apron, garage blocks and a graded service road
   behind them. The start/finish line and grid boxes sit on the actual level grid.
5. Recompile the complete road/run-off ribbon and its terrain cutout. Service
   grading modifies the existing terrain mesh; it does not add a hidden second
   contact surface. Material IDs and colours come from these same triangles.
6. Build continuous, welded barrier extrusions with capped gate ends. Rendered
   containment and chassis collision use the same extrusion vertices. Tyre stacks,
   guardrails, impact modules, fences and walls provide primitive appearances.
   Fence rails connect adjacent posts and follow the actual perimeter slope.
   Pit openings are real gaps; the pit wall does not cross the entry or exit.
7. Query actual compiled triangles to anchor solid garages, boards, marshal posts,
   stands and vegetation. Reject unsupported solids, skip unsuitable decorative
   sites and clear vegetation from run-offs, pits, service access and sight chords.

The maximum width budget is 44 m beyond a racing edge, locally reduced by other
legs and curvature. Construction can retry with 34 m and 26 m budgets if the
surface or clearances fail. Each retry recomputes the fans and speed guides and is
reported separately from M4's route attempts. All failing revisions leave the
currently loaded circuit intact.

## Escape guidance and its limits

The fan model allows a **0.5 s reaction**, then assumed recovery braking: 5 m/s²
on tarmac, 3.3 on gravel, 2.6 on sand and 1.65 on grass, adjusted for grade. It
allows up to **12 m/s (43 km/h)** remaining at the perimeter. This is a conservative
game design model, not a vehicle crash simulation or real-world circuit certification.

If the original reference approach cannot fit, M5 reports a lower speed guide and
propagates it into all three reference envelopes using acceleration/braking passes.
It never clips a fan and reports the original speed as having passed. The **Escapes**
overlay and **Venue evidence** show these space-limited approaches. A faster player
can still exceed the guide and hit the barrier. Full trajectory optimization,
deformable impact systems and race operations are outside this milestone.

## Contacts, materials and resources

M5 uses the central suspension ray plus two lateral material probes across a
210 mm footprint. Their material weights sum to one; they do not multiply wheel
support or tyre forces. Each tyre still resolves to one load/contact. Material
blending is wheel-local, so one wheel crossing a kerb or grass boundary does not
switch the entire car's grip.

Rolling torque, rubber grip, soil-displacement drag, roughness feedback and colour
are separate parameters. Gravel and sand have reduced grip and bounded ploughing
drag. The drag always removes energy, fades at rest and is capped relative to
contact mass/velocity; entering loose ground cannot reverse the car in one step.
There is no arbitrary instant stop or permanent bogging state. Barrier/garage
colliders interact with the chassis but are excluded from suspension ray queries.

Vegetation and facilities use primitive instance batches in 128 m cells. Distant
trees and stands use proxies; small detail disappears with distance. Reachable
solid garages and continuous barriers have colliders. Decorative vegetation,
fences, boards and stands do not. Geometry, instance resources, materials and sign
textures are released when a circuit is replaced.

## Validation

The complete regression suite passes **142 tests across 11 files**. New checks cover:

- Map handedness at multiple vehicle headings and invertible terrain projection.
- Retained qualified M4 fingerprints, immutable road profiles and scenery independence.
- Periodic run-off widths, fitted fan paths, paved pit merges and service continuity.
- Manifold road/terrain seams and welded/capped barrier meshes.
- Wheel-local material blending with unchanged total support load.
- Barrier roofs excluded from suspension, and contained low-rebound chassis impacts.
- Dissipative, bounded loose-surface forces and progressive gravel/sand coast-down.
- A full pit entry/lane/exit at approximately 48 km/h.
- Oblique low/raised kerb crossings at 8 and 20 m/s, without a launch.
- Complete FF/FR/MR/AWD laps on dressed touring and GP circuits.
- Resource and generated sign-texture disposal on replacement.

Browser checks covered preview invalidation, scenery-only regeneration with an
unchanged geometry fingerprint, escape overlays, venue evidence, loading/replacing
touring and 7.5 km GP venues, keyboard acceleration, the paved pit start and its
advisory, and separate kerb/asphalt wheel contacts. The actual downloaded JSON
included venue settings, accepted geometry and the matching construction
fingerprint; console warning/error checks were clear. The saved custom AWD setup
remained in place throughout circuit replacement.

The production build passes strict TypeScript checking. See the
[construction qualification report](research/m5-qualification.json) for the seeded
campaign, recipes, coverage, measured times and extreme cases.

```sh
npm test -- --maxWorkers=2
npm run build
npm run qualify:m5 -- --count=128 --workers=4
npm run report:m5
```

The qualification campaign compiled **128/128** complete venues: 32 per theme,
zero construction failures and zero M4 base fallbacks. It includes both families,
both terrain settings, all rhythms, low/raised kerbs, enabled/disabled pits and
dense scenery cases. The source/lockfile hash is **`6282afb450af1fb8`**. Four workers
completed the campaign in 114.6 s on the Ryzen 5 5600X / 32 GiB development desktop,
while the regression tests also ran.
The largest case contains 328,764 shared surface triangles and the densest contains
1,988 placed props. Parallel qualification times are not browser latency claims.

The [serial browser benchmark](http://127.0.0.1:5173/docs/research/m5-worker-benchmark.html)
uses the production worker, including startup, construction and typed-buffer
transfer. All 12 previews passed with no fallback: **0.94–3.61 s**, median
**1.97 s**, and at most **7.13 MiB** of transferred surface buffers on the same
desktop. See the [recorded browser measurements](research/m5-browser-budget.json).
That buffer total excludes JavaScript objects, Rapier allocations and GPU memory.
GPU/frame-rate certification on reference hardware and physical gamepad
checks remain separate; unattended embedded browser frame clocks can throttle even
the baseline proving circuit.
