# v0.3.0 — driving audio update

Release date: **27 October 2026**. Branch: `main`. Annotated tag: `v0.3.0`.

The owner accepted the integrated engine and tyre sounds as enjoyable driving
feedback and requested this separate audio version. It promotes the development
audio feature and the requested pre-release recording cleanup. Preparation uses
`codex/release-v0.3.0`; the previous `v0.2.0` and `v0.1.0` tags remain intact.

## Changed

- **Engine:** combustion pulses and short exhaust paths give the accepted low
  body/rumble character. Actual RPM, load, shifts and overrun drive the sound.
  The accepted base is shared across vehicle families, ready for later voicing.
- **Tyres:** four independent sources generate an evolving screech from each
  wheel's contact, slip and recent history. Entry, holding and recovery change
  spectral character independently of loudness. Low/zero load and contact loss
  are handled without applying load weighting twice.
- **Listening controls:** master, engine, tyre and surface/impact levels; headphone,
  stereo and mono modes; spatial wheel positions; axle tone difference; softer
  squeal; labeled wheel/channel auditions; persistent mute and gesture activation.
- **Runtime:** bounded readiness, mute/resume and setup replacement; explicit
  processor retirement; a stale-control output fade; native surface/kerb/impact
  branches and output headroom. Exact noise-loop boundaries retain the Vivaldi fix.
- **Tuning playground:** live synthesized comparisons, short examples, manual
  controls and versioned presets remain available without source recordings.

The accepted numerical tyre model is included as a static application asset.
It contains reference-derived frequency/strength trajectories, initial oscillator
phases and residual spectral magnitudes. Oscillators and fresh seeded noise render
the output continuously; no original WAV, recorded comparison or residual waveform
is played or included. Source/comparison playback pages and serving routes were
removed on the feature branch before release. See [cleanup](../research/audio-recording-cleanup.md)
and [parameter provenance](../research/audio-model-provenance.json).

## Upgrade and saved data

Package and lockfile versions are **0.3.0**; dependency versions are unchanged.
Use `npm ci` and `npm run build`, or `npm run dev` for the workbench. The driving
app and live playground need no local reference WAV or preparation endpoint.

The existing compatibility fingerprint includes package-lock metadata. This
version bump therefore changes the saved-result comparison key even though the
physics/race code is unchanged. Earlier bests/ghosts remain stored under their
original keys; they are not deleted or silently reclassified as new release
records. Garage, setup, circuit-library and sound-preference formats are unchanged.
Browser storage remains tied to its origin, including the port.

## Validation

Release-candidate regression, strict TypeScript/production build and standalone
package checks are pending on the preparation branch. Main/tag publication occurs
only after they pass; the completed record will be linked here.

The accepted driving integration already has a short 21.55-second actual-app
launch/shift/stop/relaunch record at 48 kHz, with all four wheel paths active and
no recorded signal/context/app-stall failures. Its original fingerprint/scope
remains in [that record](../research/reference-audio-integration.json).
The release does not rerun generation, M8 timing/renderer campaigns, a human
channel-identification study or the excluded 20-minute endurance test. Their
unchanged implementations retain historical evidence.

## Scope

This is an audio update over the existing M0–M8 solo sandbox. It adds no AI grid,
multiplayer, weather, damage, tyre wear or new generation behavior. Vehicle-family
engine voicing and further mix tuning can follow normal targeted development work.
Automated digital measurements do not certify human localization, acoustic latency
or hardware underruns. The existing large Three.js/Rapier build warning remains.
